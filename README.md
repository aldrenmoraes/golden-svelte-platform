# Golden Svelte Platform

A governed SvelteKit 5 scaffold. Clone it, describe your project in `project.manifest.yaml`,
activate it, and start building domain modules on top of a platform that already ships
authentication, RBAC, PostgreSQL, telemetry, i18n, theming, Docker, and a release pipeline.

The platform rules are in [`AGENTS.md`](AGENTS.md) and [`.scaffold/policies/`](.scaffold/policies).
They are authoritative — read them before changing anything.

## Requirements

| Tool          | Version  | Notes                                             |
| ------------- | -------- | ------------------------------------------------- |
| Bun           | `1.3.14` | Package manager, task runner, test runner, server |
| Docker Engine | 25+      | Local infrastructure and production images        |
| PostgreSQL    | 17       | Provided by `compose.yaml`                        |

Bun replaces npm, pnpm, and yarn everywhere in this repository, and `bun test` replaces Vitest.

## 1. Clone the scaffold

```sh
git clone <your-fork-url> my-app
cd my-app
bun install
```

Point the clone at your own remote before the first commit:

```sh
git remote set-url origin <your-repository-url>
```

## 2. Describe the project in `project.manifest.yaml`

`project.manifest.yaml` is the single source of truth for generated code. Edit it before writing
any feature. The fields that shape the scaffold:

| Section         | What to set                                                                                       |
| --------------- | ------------------------------------------------------------------------------------------------- |
| `project`       | `name` (kebab-case, used for image and cookie names), `displayName`, `description`                |
| `platform`      | Feature switches: `auth`, `rbac`, `postgres`, `telemetry`, `docker`, `i18n`, `themes`, `releases` |
| `domain`        | `boundedContexts`, `roles` (each role `code` becomes an RBAC role), `entities`                    |
| `observability` | `serviceName` and `piiFields` that must never be logged                                           |
| `delivery`      | `dockerComposeProject` and the `publicHost` Traefik routes                                        |
| `experience`    | `sourceLocale`, `supportedLocales`, route strategies, theme defaults                              |
| `release`       | `initialVersion`, `channel`, `commitConvention`                                                   |

Roles declared here must match the roles in
[`src/lib/server/auth/access-control.ts`](src/lib/server/auth/access-control.ts), which is where
permissions are granted.

## 3. Activate the scaffold

Preview the files activation would write, then apply them:

```sh
bun run scaffold:plan       # dry run: prints every generated artifact, writes nothing
bun run activate            # writes the generated artifacts (alias of scaffold:activate)
bun run scaffold:refresh    # re-runs activation over existing generated artifacts (--force)
```

Activation only ever writes generated artifacts (files marked `Generated by scripts/activate.ts`,
such as `src/lib/config/project.ts` and `src/lib/theme/config.ts`). It never deletes domain code,
so it is safe to re-run after editing the manifest.

## 4. Configure the environment

```sh
cp .env.example .env             # local `bun run dev`
cp .env.dev.example .env.dev     # containerised development stack
cp .env.prod.example .env.prod   # production stack
```

`BETTER_AUTH_SECRET` must be at least 32 high-entropy characters. `ORIGIN` (and `PUBLIC_APP_URL`
in the compose env files) must be the exact public URL, or auth callbacks and the origin check on
mutating routes will reject requests.

## 5. Run it locally

Against a database you already have running:

```sh
bun run db:push      # sync the schema for the first run
bun run dev          # http://localhost:5173
```

Or bring up the whole stack — app, PostgreSQL, and the OpenTelemetry collector — in containers.
Migrations run to completion before the web server starts:

```sh
bun run dev:containers
```

## 6. Verify before every commit

```sh
bun run format       # Prettier writes
bun run verify       # svelte-check + Prettier check + ESLint + bun test + locale parity
```

`bun run verify` is the aggregate gate and must report zero errors. CI
([`.github/workflows/ci.yml`](.github/workflows/ci.yml)) runs the same gate, then `bun run build`,
then a Docker image build, on every push to `main` and every pull request.

## Building a domain module

[`src/lib/server/modules/sample/`](src/lib/server/modules/sample) is the reference blueprint. Copy
its five files and keep the layering:

| File             | Responsibility                                                              |
| ---------------- | --------------------------------------------------------------------------- |
| `schema.ts`      | Drizzle table plus the Zod input contracts                                  |
| `repository.ts`  | All database access, behind an interface the service depends on             |
| `policy.ts`      | The permissions the module is governed by, checked with `requirePermission` |
| `service.ts`     | Business rules: authorize, validate, apply, then write audit context        |
| `sample.test.ts` | Unit tests that exercise the service and policy against a fake repository   |

Rules that the review gate enforces:

- Page and route components never touch PostgreSQL; they call a service.
- Every mutating route authenticates a session, authorizes a declared permission, validates its
  input, and logs structured audit context.
- Mutating API routes also call `requireSameOrigin` from `$lib/server/security/origin`.
- Every user-facing string is a Paraglide message, updated in all four locales in one change.
- New tables are re-exported from `src/lib/server/db/schema.ts`, then `bun run db:generate`.

## Commands

| Command                  | What it does                                         |
| ------------------------ | ---------------------------------------------------- |
| `bun run dev`            | Vite dev server                                      |
| `bun run build`          | Production build (`adapter-node`)                    |
| `bun run start`          | Serve the build with Bun                             |
| `bun run verify`         | Aggregate gate: check, lint, test, i18n              |
| `bun run test`           | `bun test` (platform suites and module tests)        |
| `bun run db:generate`    | Generate a migration from the Drizzle schema         |
| `bun run db:migrate`     | Apply migrations                                     |
| `bun run db:studio`      | Drizzle Studio                                       |
| `bun run i18n:check`     | Fail if the locale files drift apart                 |
| `bun run scaffold:plan`  | Dry-run activation                                   |
| `bun run activate`       | Activate the manifest (alias of `scaffold:activate`) |
| `bun run dev:containers` | Full stack with `compose.dev.yaml`                   |
| `bun run prod:up`        | Deploy the production stack (`--confirm` required)   |
| `bun run release`        | Tag and changelog per the manifest release settings  |

## Project layout

```
src/lib/server/auth/        Better Auth, access control, requirePermission guard
src/lib/server/db/          Drizzle handle and aggregated schema
src/lib/server/modules/     Domain modules (schema, repository, service, policy, tests)
src/lib/server/security/    Security headers and origin/CSRF validation
src/lib/server/observability/ Structured logging with trace and request context
src/routes/                 Pages and API routes
docs/product-brief.md       What the project is for — fill this in first
.scaffold/policies/         Architecture, security, observability, and testing policies
tests/platform/             Platform-level suites
```
